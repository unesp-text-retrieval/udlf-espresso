# LaTeX Re-Ranking Tables

## Purpose

This script generates **publication-ready LaTeX tables** summarising the effectiveness of UDLF unsupervised re-ranking methods across datasets, retrieval models, and evaluation metrics. The tables are designed for direct inclusion in a research paper or dissertation via `\input{}`.

Two layout modes are available:

| Mode | Best for | What it shows |
|------|----------|---------------|
| **complete** | Dissertations, appendices | Every model × method × K combination with baseline rows and all requested cutoffs (@20, @50, @200) |
| **compact** | Papers (space-constrained) | One baseline row + one best-method row per model at @20, with inline Δ% on the rerank values |

Both modes also emit a **cross-dataset summary table** that picks the single best (model, method, K) per dataset.

## Quick Start

```bash
conda activate udlf-espresso

# Default: complete mode, all cutoffs, all datasets
python scripts/generate_latex_tables.py

# Compact mode for a paper (only @20)
python scripts/generate_latex_tables.py --mode compact

# Specific cutoffs and datasets
python scripts/generate_latex_tables.py --cutoffs 20 50 --datasets bbc-news mental-health scifact

# Custom output path
python scripts/generate_latex_tables.py --output outputs/paper-assets/tables.tex
```

Output `.tex` file lands in `outputs/paper-assets/latex_rerank_tables.tex` by default.

### Full CLI Reference

| Flag | Default | Description |
|------|---------|-------------|
| `--data` | `scripts/experiment_progress_data.json` | Path to the experiment results JSON |
| `--output` | `outputs/paper-assets/latex_rerank_tables.tex` | Output `.tex` file |
| `--datasets` | all in data | Subset of datasets to include |
| `--cutoffs` | `20 50 200` | Cutoff values for column groups (complete mode) |
| `--mode` | `complete` | `complete` or `compact` |
| `--no-summary` | false | Skip the cross-dataset summary table |

## Data Source

The script reads **`scripts/experiment_progress_data.json`** — a structured JSON file containing all experiment results. This file is generated by the experiment monitoring pipeline and has the following schema:

```json
{
  "configuration": {
    "datasets": ["arguana", "scifact", ...],
    "models": ["bm25", "miniLM-L6-v2", ...],
    "methods": ["cprr", "bfstree", "rdpac"],
    "k_values": [1, 3, 5, 10, 20, 30, 40, 50, 75]
  },
  "baseline_comparison": {
    "<dataset>": {
      "<model>": {
        "<method>": {
          "<k_value>": {
            "precision@20": {
              "baseline": 0.4123,
              "rerank": 0.5678,
              "improvement_pct": 37.7
            },
            "map@20": { ... },
            "recall@20": { ... },
            "precision@50": { ... },
            ...
          }
        }
      }
    }
  }
}
```

Each metric entry contains three fields:
- `baseline`: the retrieval-only score (before UDLF re-ranking)
- `rerank`: the score after applying UDLF re-ranking
- `improvement_pct`: relative percentage change `(rerank - baseline) / baseline × 100`

## High-Level Algorithm (Reproducible Without This Script)

If the Python script is lost, here is the exact logic to reproduce the tables from the JSON data:

### Step 1 — Best K Selection

For each `(dataset, model, method)` triple, find the K value that **maximises `precision@20.improvement_pct`**. If two K values tie, prefer the smaller K (more efficient re-ranking).

```
best_K(dataset, model, method) = argmax_K  precision@20.improvement_pct
                                  ties broken by min(K)
```

### Step 2a — Complete Table (one per dataset)

**Columns**: `Method | MAP@c₁ | P@c₁ | Recall@c₁ | MAP@c₂ | P@c₂ | Recall@c₂ | ...` where c₁, c₂, … are the requested cutoffs (e.g. @20, @50, @200).

**Rows** (grouped by model):
1. **Baseline row** — `"<Model> (base)"`: shows the `baseline` value for each metric.
2. **Re-ranking rows** — `"  + <Method> (K=<best_K>)"`: shows the `rerank` value. **Bold** if it improves over baseline.

Models are separated by `\midrule` horizontal rules.

### Step 2b — Compact Table (one per dataset)

**Columns**: `Method | MAP@20 | P@20 | Recall@20`

**Rows** (two per model): select the single best method across all three UDLF methods (again by highest `precision@20.improvement_pct`). For each model:
1. **Baseline row** — `"<Model> (base)"`: shows the `baseline` value for each metric.
2. **Re-ranking row** — `"  + <Method> (K=<best_K>)"`: shows the `rerank` value, **bold** if improved, with inline `{\scriptsize (+Δ%)}` suffix.

### Step 3 — Summary Table (cross-dataset)

**Columns**: `Dataset | Model | Method (K) | MAP@20 | P@20 | Recall@20`

**Rows** (two per dataset): for each dataset, find the globally best `(model, method, K)` triple by `precision@20.improvement_pct`. Show a baseline row then a re-ranking row with inline Δ%.

### Step 4 — LaTeX Formatting

- Numbers are formatted to 4 decimal places (`%.4f`).
- Improved values are wrapped in `\textbf{}`.
- Compact and summary mode show inline Δ% via `{\scriptsize (+X.Y\%)}` on re-ranking rows.
- Special characters in model/dataset names are escaped (`_` → `\_`).
- Tables use `booktabs` (`\toprule`, `\midrule`, `\bottomrule`).

## Design Decisions

### Why select best K by Precision@20 specifically?
Precision@20 directly measures the proportion of relevant documents in the user-visible top-20 results — the metric most aligned with user experience. MAP and Recall often agree on the same best K, but when they diverge, P@20 is the most interpretable tiebreaker.

### Why bold improved values?
In a table with 30+ cells, readers need to instantly see *where* re-ranking helped. Bold values create a visual pattern — readers can scan the table and immediately grasp that most cells improved (many bolds) or that improvements are selective (few bolds).

### Why two modes?
A dissertation can afford a full page per dataset showing every model × method combination. A 12-page paper cannot. Compact mode reduces each dataset to ~5 rows while preserving the key insight: "for each retrieval model, this UDLF method at this K improved P@20 by this much."

### Why include a summary table?
Reviewers want a quick answer: "across all datasets, does UDLF re-ranking help?" The summary table answers this in one glance — one row per dataset, the single best configuration, all three metrics with Δ%.

```latex
\begin{table}[htbp]
  \centering
  \caption{Re-ranking effectiveness on \textbf{BBC-News}. Best $K$ is chosen
           per model/method by highest P@20 improvement. Bold values indicate
           improvement over the retrieval baseline.}
  \label{tab:rerank-bbc-news}
  \small
  \begin{tabular}{l|ccc|ccc}
    \toprule
     & \multicolumn{3}{c}{@20} & \multicolumn{3}{c}{@50} \\
    Method & MAP & P & Recall & MAP & P & Recall \\
    \midrule
    BM25 (base) & 0.3421 & 0.3421 & 0.3421 & ... \\
    \quad + CPRR ($K$=75) & \textbf{0.4567} & \textbf{0.4567} & ... \\
    \quad + BFS-TREE ($K$=50) & \textbf{0.4123} & ... \\
    \quad + RDPAC ($K$=75) & ... \\
    \midrule
    Contriever (base) & ... \\
    ...
    \bottomrule
  \end{tabular}
\end{table}
```

### Compact Mode

```latex
\begin{table}[htbp]
  \centering
  \caption{Best re-ranking result per model on \textbf{BBC-News}

  \begin{tabular}{lccc}
    \toprule
    Method & MAP@20 & P@20 & Recall@20 \\
    \midrule

```

## Metrics Covered

| Family | Key in JSON | Display | What it measures |
|--------|------------|---------|-----------------|
| MAP | `map@{c}` | MAP | Mean Average Precision — overall ranking quality |
| Precision | `precision@{c}` | P | Fraction of top-c results that are relevant |
| Recall | `recall@{c}` | Recall | Fraction of all relevant docs found in top-c |

Available cutoffs: **@20**, **@50**, **@200** (configurable via `--cutoffs`).

## LaTeX Requirements

The generated `.tex` file requires only the `booktabs` package:

```latex
\usepackage{booktabs}
```

Include in your paper:

```latex
\input{latex_rerank_tables.tex}
```

## Regenerating After New Experiments

If new experiments are added to the GCS bucket:

1. Re-run the experiment monitoring script to update the JSON:
   ```bash
   python scripts/monitor_experiment_progress.py
   ```
2. Re-generate the tables:
   ```bash
   python scripts/generate_latex_tables.py --mode compact
   ```

The script automatically picks up any new datasets, models, or K values present in the updated JSON.
